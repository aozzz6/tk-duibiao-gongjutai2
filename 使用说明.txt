TikTok 工作台 · 本地最终版 2.0.0（2026-10-22）

一、开始使用
把整个“TikTok工作台_本地最终版”文件夹复制到 U 盘，双击 TikTok工作台.exe。
适用 Windows 10/11 的 64 位电脑。不要只复制 EXE；resources 和 DLL 必须一起携带。
程序约 5.9 GB，已包含 Python、FFmpeg 与 Whisper medium CPU 转写模型。
无需安装 WorkBuddy，无需 Agent、技能目录或转交对话。

二、数据各自保存在电脑上
数据目录：%LOCALAPPDATA%\TikTokWorkbench。
不同电脑、不同 Windows 用户首次启动都是空白；同一用户再次启动保留之前的记录。
账号、台账、附件、模型密钥、监控 Cookie、反推素材和报告不跟 U 盘程序一起移动。
“工作台 → 打开本机数据目录”可以查看和自行备份。
同机升级保留原有数据；新电脑需要自行配置网络与模型。

三、本机执行和模型服务的区别
采集编排、转写、建表、回填、统计报告、视频抽帧、报告保存和定时任务由软件直接执行。
翻译、AI 内容分析、视觉反推和提示词精修，由软件直接调用你配置的模型服务。
可以使用远程 API，也可以填写兼容的本机模型 API 地址。远程服务需要联网，可能计费。
本软件附带的 Whisper 只负责语音转文字，不是文本分析或视觉大模型。
不配置大模型仍可使用本地确定性功能；需要联网的平台采集仍受平台权限、登录态和代理影响。

四、独立任务
侧栏“独立任务 · 翻译与报告”可分别执行：
- 建立台账表：补齐规范表头；不强制覆盖已有的不匹配表头。
- 回填与校验：读取抓取、转写产物，幂等入账并重开文件核验。
- 统计报告：汇总本机台账，保存 HTML 和 JSON，不调用模型。
- 增量采集与归档：下载、抓取、转写、台账同步、校验和报告。
- 中文翻译并回填：按原文、视频 ID 和行号核对后填补待译内容。
- AI 内容分析：依据真实统计和最多40条按播放量排序的样本文案生成分析。
- 完整整理：建表、回填、报告；勾选追加 AI 后再翻译和分析。
可查看日志、停止任务、打开报告。离开任务页面不会自动停止后台任务。

五、文本与视觉模型设置
顶部菜单“工作台 → 设置”：分别填写文本模型与视觉模型的 API 地址、API Key、模型名称。
使用 chat-completions 文本/图片协议；一般基础地址以 /v1 结尾，也支持完整 /chat/completions 地址。
本机 localhost 兼容服务允许不填密钥；视觉模型必须支持图片输入。
模型连接直连，不使用采集代理。保存后自动重启，运行中的任务需要先完成或停止。
自动翻译默认关闭；明确启用后，采集同步台账完成时会自动调用文本模型。

六、提示词反推（没有交接包）
可输入 TikTok 视频链接生成素材，也可点“导入本地视频”（mp4/mov/webm/mkv，上限500MB）。
本地导入直接处理原片，不下载平台视频；抽帧、场景检测、参数读取不调用模型。
素材就绪后点“AI 反推”，软件直接调用视觉模型读帧，生成分镜、提示词、旁白和 HTML 报告。
报告完成后可点“本地精修”，填写调整要求并执行；保留分镜事实，修改生成提示词与旁白。
精修前会备份原报告；模型分镜索引不完整或结果无效时不覆盖原报告。
本地素材重建保留原片，清理并重建抽帧、首帧和报告。链接素材重建可能重新下载。
AI 结果仍需结合原始视频复核；不可辨认或缺失的事实不应当作已确认结论。

七、榜单监控与已下线内容
本次保留原工作台的榜单快照/差分模块；EchoTik 已按最新版本下线，没有重新打包。
在软件设置中填写榜单登录 Cookie 与监控源 JSON，再到“爆品监控”执行探测、快照或差分。
配置示意：{"sources":[{"name":"source_1","type":"cc_ssr","url":"填写有权限使用的实际榜单地址","params":{},"enabled":true}]}。
cc_api 类型使用站内 path；cc_ssr 类型使用完整 http(s) URL。默认 sources 为空，不自动抓取。
未配置来源会明确提示配置，不把空跑伪装成已获得榜单数据。

八、定时与退出
“定时自动运行”中选择任务、时间和账号，启用并保存。含 AI 的任务需要先配置模型。
软件必须运行、电脑不能休眠；时间按当前电脑时区。当天错过时刻后启动会补执行一次。
每天最多自动执行一次，手动执行不计入此限制；运行中的任务不会被并发的定时任务覆盖。
关闭主窗口会结束后台；有任务（包括视频反推）时会询问是否结束任务。
后台使用进程树约束，异常退出时也会清理子进程；退出软件后再安全弹出 U 盘。
“工作台 → 查看日志”可以查看 desktop.log 和 backend.log。
